# kbd-debounce — программный фильтр дребезга клавиатуры для Linux

*English version: [README.md](README.md)*

Клавиатуры MacBook с механизмом «бабочка» (2015–2019) со временем начинают дребезжать: одно нажатие даёт две буквы. В macOS это частично скрывает прошивка и система, в Linux — нет. `kbd-debounce` убирает ложные повторы программно, на уровне evdev, не трогая ни драйвер, ни раскладку.

Фильтр написан и отлажен на MacBook 12" (MacBook10,1, 2017, драйвер `applespi`) под Manjaro с GNOME на Wayland, но не привязан ни к этой модели, ни к графической среде: он работает с любой клавиатурой, которую видит evdev.

## Как это устроено

Служба захватывает клавиатуру в монопольный режим (`EVIOCGRAB`), создаёт виртуальную клавиатуру `kbd-debounce` через uinput и пересылает в неё события, пропуская их через фильтр. Графическая среда видит только виртуальную клавиатуру, поэтому фильтр одинаково работает в Wayland, X11 и в текстовой консоли.

Простой порог по времени («игнорировать повтор раньше N мс») проблему не решает. Измерения показали, что дребезг бывает двух видов:

| Вид | Пауза между отпусканием и ложным нажатием | Сколько держится ложное нажатие |
| --- | --- | --- |
| Разрыв контакта посреди нажатия | 2–50 мс | любое время (это продолжение настоящего нажатия) |
| Отложенное ложное срабатывание | 90–250 мс | 4–55 мс |

Второй вид по паузе неотличим от быстрого набора удвоенных букв («длинный», «account»): человек делает такую же паузу. Если поднять порог до 100–200 мс, фильтр начинает съедать настоящие удвоения и быстрые двойные нажатия стрелок и Backspace. Различает их другое — длительность: ложное нажатие держится не дольше 55 мс, а человек удерживает клавишу 80 мс и больше.

Отсюда две ступени:

1. **Быстрая.** Повторное нажатие той же клавиши раньше `--ms` (50 мс) после её отпускания отбрасывается сразу.
2. **С придержкой.** Повторное нажатие в окне от `--ms` до `--slow-ms` (50–250 мс), если между ними не нажималась другая клавиша, не отдаётся сразу, а придерживается на `--hold-ms` (55 мс):
   - клавишу отпустили за это время — это дребезг, нажатие и отпускание выбрасываются;
   - клавиша всё ещё нажата или нажата другая клавиша — нажатие настоящее и отдаётся дальше.

Цена решения — задержка до 55 мс, и только для повтора той же клавиши в течение четверти секунды. Обычный набор не задерживается вовсе.

Известное ограничение: настоящее повторное нажатие короче `--hold-ms`, сделанное в пределах окна, будет потеряно. На практике это очень короткие касания; если они теряются, уменьшите `--hold-ms`.

## Состав

| Файл | Назначение |
| --- | --- |
| `kbd-debounce.py` | сам фильтр (evdev → uinput) |
| `kbd-debounce.service` | служба systemd с изоляцией |
| `60-kbd-debounce.rules` | правило udev: запускает службу при появлении клавиатуры |
| `kbd-diag.py` | диагностика: что проходит сквозь фильтр |

## Установка

Нужны Python 3.10 или новее и библиотека python-evdev:

```
pamac install --no-confirm python-evdev      # Manjaro
sudo pacman -S python-evdev                  # Arch
sudo apt install python3-evdev               # Debian, Ubuntu
sudo dnf install python3-evdev               # Fedora
```

Узнайте имя своей клавиатуры:

```
grep -E '^N: Name' /proc/bus/input/devices
```

Если оно отличается от `Apple SPI Keyboard`, замените его в двух местах: в параметре `--name` в `kbd-debounce.service` и в `ATTRS{name}` в `60-kbd-debounce.rules`.

Установите файлы и запустите фильтр:

```
sudo install -m 755 kbd-debounce.py /usr/local/bin/kbd-debounce.py
sudo install -m 644 kbd-debounce.service /etc/systemd/system/kbd-debounce.service
sudo install -m 644 60-kbd-debounce.rules /etc/udev/rules.d/60-kbd-debounce.rules
sudo systemctl daemon-reload
sudo udevadm control --reload
sudo udevadm trigger --action=add --subsystem-match=input
```

Проверка:

```
systemctl status kbd-debounce
```

В журнале должна появиться строка вида `устройство: /dev/input/event4 (Apple SPI Keyboard), порог 50.0 мс, окно 250.0 мс, удержание 55.0 мс`.

У службы намеренно нет секции `[Install]`, и `systemctl enable` для неё не нужен: её запускает правило udev в момент появления клавиатуры — при загрузке и после каждой перепривязки драйвера (например, после сна). Если клавиатура исчезает, фильтр завершается с кодом 0 и будет запущен снова тем же правилом.

Служба требует `/dev/uinput`. Если такого узла нет, загрузите модуль: `sudo modprobe uinput`, а для постоянной загрузки создайте файл `/etc/modules-load.d/uinput.conf` со строкой `uinput`.

## Настройка порогов

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `--name` | `Apple SPI Keyboard` | часть имени устройства (без учёта регистра) |
| `--ms` | 50 | повтор раньше этого времени отбрасывается безусловно |
| `--slow-ms` | 250 | верхняя граница окна подозрительных повторов |
| `--hold-ms` | 55 | на сколько придерживается подозрительное нажатие |
| `--log` | выключено | писать в журнал каждый отброшенный повтор |

Пороги меняются в строке `ExecStart` файла службы; после правки — `sudo systemctl daemon-reload && sudo systemctl restart kbd-debounce`.

Подбирать их лучше по собственной статистике. С ключом `--log` (в приложенном файле службы он включён) каждый отброшенный повтор попадает в журнал:

```
journalctl -u kbd-debounce | grep дребезг
```

```
дребезг KEY_V: пауза 25 мс, удержание 92 мс (быстрый)
дребезг KEY_N: пауза 119 мс, удержание 49 мс (придержан)
```

Как читать:

- **Двойные буквы всё ещё проскакивают** — запустите `sudo ./kbd-diag.py --seconds 90 --max-ms 500` и наберите обычный текст. Утилита слушает виртуальную клавиатуру, то есть показывает прошедшее сквозь фильтр: паузу и удержание каждого повтора. Повторы с коротким удержанием, превышающим `--hold-ms`, означают, что `--hold-ms` нужно увеличить; с паузой больше `--slow-ms` — увеличить окно.
- **Пропадают настоящие двойные нажатия** — посмотрите в журнале записи «быстрый» с паузой, близкой к `--ms`, и удержанием от 80 мс: это ваши нажатия, `--ms` нужно уменьшить. Если пропадают записи «придержан» с удержанием, близким к `--hold-ms`, — уменьшить `--hold-ms`.

Для справки, измерения на одном экземпляре MacBook10,1: при `--ms 80` фильтр съедал быстрые двойные нажатия стрелок, Backspace и CapsLock (паузы 50–76 мс, удержание от 87 мс); порог по удержанию 65 мс съедал настоящие удвоения букв при быстром наборе.

## Безопасность

Фильтр видит все нажатия клавиш, поэтому работает от root, но с максимально урезанными правами: `ProtectSystem=strict`, `ProtectHome=yes`, пустой `CapabilityBoundingSet`, без сети (`RestrictAddressFamilies=none`), из устройств доступны только устройства ввода и `/dev/uinput` (`DevicePolicy=closed`). Оценить изоляцию можно командой `systemd-analyze security kbd-debounce.service`.

Журнал `--log` содержит только коды клавиш отброшенных повторов, а не набираемый текст. Тем не менее, если это нежелательно, уберите ключ `--log` из `ExecStart`.

## Полезно знать

- Из-за дребезга легко трижды подряд ввести неверный пароль и получить блокировку `pam_faillock` на 10 минут. До настройки фильтра её можно отключить: `deny = 0` в `/etc/security/faillock.conf`.
- Раскладки, параметры XKB и горячие клавиши фильтр не затрагивает: виртуальная клавиатура повторяет возможности настоящей.
- Чтобы временно отключить фильтр: `sudo systemctl stop kbd-debounce` — клавиатура вернётся к прямой работе.

## Удаление

```
sudo systemctl stop kbd-debounce
sudo rm /etc/udev/rules.d/60-kbd-debounce.rules /etc/systemd/system/kbd-debounce.service /usr/local/bin/kbd-debounce.py
sudo systemctl daemon-reload
sudo udevadm control --reload
```
